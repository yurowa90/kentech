# 독립 밸런스 검사와 전략 봇

기준은 [ECON-BALANCE.md](../../docs/ECON-BALANCE.md)의 목표·계약이다. 충돌하는 절은 최신 판본을 우선하며, renew 전환은 **v1.4 B18**을 따른다. 현재 구현의 값을 기대값으로 삼지 않는다. 게임 계수와 자료 파일은 수정하지 않는다. 목표 범위는 명세의 G(게임 가정), 에너지 입력의 주민 수 비례 근사는 M(검사 장치)이다.

## 실행

저장소 루트에서:

```sh
node --check tests/league/balance.js
node tests/league/balance.js
python3 -m py_compile tests/league/bots36.py
```

엔진 검사는 `Math.random`을 예외로 막고 DOM 없이 실행한다. 도시 목록·이름·최소 시작 현금 도시는 자료에서 읽는다. 절별 `B3 통과 5/6`, 측정값을 포함한 실패 목록, 마지막 `pass N fail M`을 출력한다. 계약 필드 누락도 실패다. 실패 시 종료 코드 1.

브라우저 검사는 로컬 총괄이 기존 Playwright 환경에서 실행한다. 패키지 설치가 필요하면 이 작업 밖에서 준비한다.

```sh
python3 tests/srv.py 9430 .
# 다른 터미널; 기존 tests/.venv가 있으면 그 Python을 사용
tests/.venv/bin/python tests/league/bots36.py
tests/.venv/bin/python tests/league/bots36.py http://127.0.0.1:9430/index.html --months 36
tests/.venv/bin/python tests/league/bots36.py --quick
```

기본은 36달·7회전, `--months`는 12/24/36, `--quick`은 12달·2회전이다. 항상 36턴 상태를 만들고 지정한 달까지만 관찰한다. 전략 7종을 도시 6곳에 회전 배정하므로 전체 실행은 7회전이며, 전략마다 모든 도시를 한 번 맡는다(42개 도시×전략 표본). 빠른 실행의 빈 도시×전략 칸은 `-`로 표시한다.

화면 클릭 없이 `page.evaluate`에서 자리 요청 → host next → 정책·계획·연계선 요청 → run을 수행한다. 모든 건설 전략은 매달 `KCP.leagueAI.plan(S, R, id, BG, "balanced")`의 `plan`을 공통 기반으로 쓴다. 계약은 `{plan: {builds, lines}, econPol, ties}`이며 S·R을 변경하지 않고 지도 선택을 복원한다. 이 비교에서는 AI의 경제 정책·연계선 판단 대신 다음 전략 차이만 적용한다.

| 전략 | 공통 기반에 적용하는 차이 |
|---|---|
| nothing | 건설 없음, 정책 0인 기준선 유지 |
| base | AI 건설 계획 그대로, 정책 0 |
| diesel | 이번 달 AI가 새로 제안한 재생·저장 설비를 정격 MW 합이 정확히 같은 디젤(없거나 불가능하면 LNG·석탄) 묶음으로 전환 |
| renew | 이번 달 AI가 새로 제안한 디젤·LNG·석탄을 재생+저장으로 전환. 재생 정격과 저장 출력 각각을 원 화력 MW 이상으로 확보하고, 접속 여유가 모자라면 ESS를 추가해 먼저 배치. 변동 재생은 그달 전량 접속할 수 있는 묶음만 채택 |
| ties | AI 건설 뒤 모든 후보 연계선을 제안·수락. 상대는 기존 계획·예산·지방채 규칙 안에서 수락 |
| taxlow | AI 건설 + 주민·산업 세율 −2, 서비스 +2 |
| taxhigh | AI 건설 + 주민·산업 세율 +2, 서비스 −2 |

이미 운영한 설비·선은 유지한다. 설비 단위 때문에 diesel의 정확한 MW 전환이 불가능하면 원 설비를 유지한다. renew의 재생 정격은 날씨에 따른 실제 공급이나 화력의 확정 출력과 같다는 뜻이 아니다. 설비 전환의 자리·중복·경로 비용은 `siteRule`, `routePath`, `capex`, `spendOf`, `budget`에서 읽고, `cleanPlan`에서 잘리는 후보는 채택하지 않는다. 변환을 못 하면 AI 계획을 그대로 둔다. 실제 계획 요청의 수락과 자산 무손실도 검사한다. 현금이 지방채 하한(−debtCap)보다 작을 때는 기존 자산 유지 예외만 허용한다. 새 게임 계수는 추가하지 않는다(선 길이 80칸·연계선 2 MW는 기존 요청 프로토콜).

B18 접속 여유는 `S.grid[id].headroomMW`(공개 상태의 `grid[id]` 및 `econ.cities[id].grid`에도 존재)를 읽는다. 접속 완료·부분 예약 뒤의 잔량이므로 기존 대기의 미예약 몫, AI가 함께 제안한 변동 재생, 앞서 채택한 전환을 함께 차감한다. ESS 증가분만 1 MW당 여유 +1 MW로 반영하며, 저장 기수는 원 화력 출력과 접속 부족분을 모두 채울 만큼 올림한다. ESS 자리를 먼저 확보하고 연결 비용까지 예산에 포함한다. 접속 계약 누락·예산 부족·자리 부족이면 원 화력을 유지한다.

ESS는 월 접속 처리량을 늘리지 않는다. 후보 계획을 상태에 반영하지 않고 실제 `gridStatus(..., true)` 경로로 예측해, 기존 대기와 다른 신규 재생을 처리한 뒤 전환 설비가 전량 접속되는지 확인한다. 같은 달의 처리량 재사용도 허용하지 않는다. 접속 계산이 연계선 양 끝 도시의 지도를 선택하므로 계산 뒤 대상 도시로 복원한다. 소수력 등 `BLD.variable`이 없는 재생에는 변동 재생 접속량을 부과하지 않는다.

공통 계획을 모두 계산한 뒤 요청을 적용하므로 도시 요청 순서가 AI 입력을 바꾸지 않는다. 1월 연 투자·중간 보완 시점은 AI 계약을 따른다. 연계선은 기반 건설 뒤 남은 예산으로 처리하고, 제안·수락 결과와 거절 사유를 원자료에 남긴다. 같은 제안은 다음 달에도 수락을 재시도한다. 회전마다 같은 방 씨앗을 쓰며 사건 분포는 별도 200개 방에서 검사한다.

`leagueAI.plan`이 없을 때만 `calib.py`의 AUTO 문자열과 이전 건설 방식을 사용한다. 이 경우 결과표에 **legacy fallback (leagueAI 없음)**을 표시한다. AI 실행 예외를 대체 경로로 숨기지 않는다.

표준출력과 `tests/results/bots36.md`에 평균 결과·도시×전략 점수·실패 목록을 남긴다. 표에는 전략별 정전 평균, **평균 접속 대기 MW·평균 출력제어 MWh**, **같은 도시의 7전략 중 1위 횟수/6**를 표시하고, `nothing`을 뺀 전략 평균 점수 최고−최저 차이를 출력한다. 공동1위는 모두 세며, 리그 상대 순위와 구분한다. 부분 실행은 7전략 점수가 모두 있는 도시만 1위를 집계하고 비교 완료 도시 수를 표시한다. `B16 strategy-dominance: <전략> 1위 n/6`은 보고 줄이며 단언하지 않는다.

접속 대기는 운영 뒤 달별 MW 평균이다. 출력제어는 엔진의 7일 보고를 각 달의 `mdays / 7`로 환산한 뒤 월 평균을 낸다. 두 값은 도시별 결과와 `strategySummary.meanWaitingMW`·`meanCurtailMWh`에도 남긴다. 누락된 측정값은 0으로 대체하지 않고 `-`로 표시한다.

`tests/results/bots36.json`에는 달별 재정·에너지·경제 상태·제안·최종 계획, 월별 계획 요청/설비 전환/유지 내역, 연계선 요청, `strategySummary`를 남긴다. `fin` 등 점수 부분이 없으면 표에는 `-`를 쓰며 엔진 계약 검사에서는 실패한다. 끝은 `checks N fail M`, 실패 시 종료 코드 1이다. 페이지 오류·콘솔 error/warning도 실패다. 로컬 주소만 허용하고 외부 요청을 차단한다. 외부 글꼴 CSS는 네트워크 없이 빈 스타일시트로 대체한다.

## 명세 해석

- B1 감소·회복은 실제 주민 수의 시작 대비 변화다. 보통 조건의 몫 변화는 퍼센트포인트가 아닌 **시작 몫 대비 상대 %**다. 40씨앗 평균을 달마다 계산하고 36달 중 최대 절댓값을 판정한다. 회복은 씨앗별 최대 손실의 평균과 마지막 손실의 평균을 비교한다.
- 보통 입력은 주민10만명당 하루25MWh×30일, 원가0.012억/MWh, 지역 CO₂ 하루2.5t·소비 CO₂ 4t, 재생15%, spareMW100으로 구성한다. opex=demMWh×costPerMWh이며 정책·거래·건설은 0이다. 모든 시나리오는 먼저 이 조건으로 보정한다.
- B2의 '첫 달 보정 뒤'는 첫 monthStep 직전 calibrate 결과로 해석했다. 상태의 approval0가 이 시작값을 보존해야 한다.
- B3은 한 도시의 정책만 바꾸고 나머지는 보통 조건으로 둔다. 격자는 주민·산업 세율을 함께 움직이는 세율5단계×서비스5단계다. 동일한 한 씨앗에서 36달 점수를 비교하며 공동1위도 해당 정책의 1위로 센다. resTax 약3배·svcStep 0.5 수준·fin 가중0.10 안팎은 권고값이므로 정확한 값 대신 행동 목표와 명시적 상한을 판정한다.
- B4의 원가 하한 검사는 **매달 실제 입력 공급량의 가중 평균**을 두 입력에서 같은 0.012로 유지한다(B11 우선). 원가0이면서 공급량이 있는 도시는 평균에 포함한다. 차익·매출 허용오차 0.01억은 기존 금액 반올림 기준을 유지한다. 원가10배 도시의 음수 차익 기대값도 입력 공급량으로 독립 계산한다.
- B7은 **주민세+산업세+국가 지원금만** 포함한다(B11 우선). 12달 전에는 지금까지 관측한 달 평균×12를 매달 갱신하고, 이후에는 최근12달 합계에 debtCapRatio를 곱한다. 지원금도 실제 받은 달의 세입이므로 첫 달에는 12배 환산되고 다음 달 한도가 20% 넘게 줄 수 있다. 거래 급증과 무거래 대조군의 한도 동일 단언은 유지한다. 반올림 오차는 기존 0.1억이다.
- B8은 주민·에너지 규모가 달라도 자격 차이가 순위를 가리지 않도록 workers1·mw1·rePct0·unsMax100의 동일한 검사 제안을 사용한다. '동일 입력'은 각 도시 주민 수에 비례한 보통 입력이다. 최소 도시의 정책은 12달 반영 후 평가한다.
- B9 '계절 평균1.2 안팎·예전 분포 유지'는 기존 1개+40%두개의 평균1.4도 포함하는 1.0~1.6으로 기록한다. 달 모드의 0/1개 조건과 두개≤10%는 별도로 모두 단언한다.
- B10 작은 뉴스는 보통 조건 초기3달의 이주·이전 뉴스0으로 판정한다. 뉴스 문턱 수치는 명세에 없어 임의의 문턱을 강제하지 않는다. 회수액 줄의 이름은 fiscal.salvage로 정했다(명세는 이름을 확정하지 않음). 사건 줄은 명세가 정한 fiscal.eventBonus다. 현금 항등식 오차는 1e-6억이다.
- 봇의 B6 비율은 용어의 운영 수지에서 eventBonus를 제외해 계산한다(B9 별도 보고 요구). CO₂는 전체 관찰 달의 소비 CO₂ 합/달별 주민 수 합(t/인·월), 정전은 달별 비율 평균이다. 평가 통과는 12달마다 실제 pass=true인 횟수다.

샌드박스에서는 브라우저를 실행하지 않는다. page.evaluate JS 문법은 다음처럼 임시 디렉터리에서 검사하며 파일을 남기지 않는다:

```sh
def constant(file, key):
    module = ast.parse(pathlib.Path(file).read_text())
    return next(ast.literal_eval(n.value) for n in module.body
                if isinstance(n, ast.Assign) and any(
                    isinstance(t, ast.Name) and t.id == key for t in n.targets))
js = constant('tests/league/bots36.py', 'JS')
auto = constant('tests/league/calib.py', 'AUTO')
with tempfile.TemporaryDirectory(prefix='bots36-syntax-') as tmp:
    p = pathlib.Path(tmp) / 'evaluate.js'
    p.write_text(auto + '\nconst run = (' + js + ');\n')
    subprocess.run(['node', '--check', str(p)], check=True)
PY
```
