## (b) league.js S7

변경 위치: 880–881(원인 이름·선택 허용), 2364·2375(소비 탄소 비교와 시험 범위), 2417–2427(이웃 단계·계통 단서), 2514·2526–2537(첫 달), 2549–2550(첫 달 단서), 2804–2809·2823–2824(월간), 2899(다음에 볼 근거).

- 첫 달: **내 선택 → 날씨·운전 기간 → 사건·대응 → 이웃 거래 → 계통 수입**.
- 월간: 기존 진행·성장 몫을 없애지 않고 **내 선택 → 날씨·계절·운전 기간 → 사건·대응 → 접속·공사·기술 진행 → 도시 성장·연료 값 → 이웃 거래 → 계통 수입**. 월간을 5단계로 합치면 기존 원인 의미까지 바뀌므로 7단계를 선택했다.
- 자체 시뮬레이션 단계는 수입 없이 계산한다. 이웃 단계는 기존 `flow`의 손실 후 도착량에서 화력 대체 `sub`를 빼서 복원한다. 마지막 단계의 수입을 켠 값은 실제 `runRound` 결과를 사용한다. 계통 수입량의 시간별 식을 UI에 복제하지 않는다.
- 첫 달 마지막 몫은 `(실제 − 이웃 단계) − (수입 있는 시험 재현 − 수입 없는 시험 재현)`이다. 따라서 시험에도 같은 수입이 있으면 마지막 몫은 **메운 절대량이 아니라 시험 대비 효과 변화**다. `부분합 + 기존 재현 차이 = 실제 − 시험`을 유지한다.
- 월간은 이웃 효과와 계통 효과 각각의 이번 달−지난달 차이를 사용한다. `부분합 = 이번 실제 − 지난 실제`이며 기존 재현 진단은 합계 밖이다.
- 저장 결과의 `flow`·`sub`·수요·정전율은 반올림되어 있다. 이 오차는 마지막 계통 몫에 남긴다. 독립적으로 계통을 꺼서 실행한 거래 사례와 마지막 몫의 차이는 0.001573%p였다.
- 단서는 “바깥 계통이 메워 준 몫의 시험/지난달 대비 변화”. 수입 상한 50%·원가 배수 1.5는 `gradeWords("G")`의 “게임 가정”으로 표시한다.
- 카드 집합을 고른 뒤 `parts` 순서대로 배치하는 기존 코드와 순서 의존 안내를 보존했다. 크기순 배치로 바꾸지 않았다. 계산·분해는 기기 안에만 남는다.
- **추가 시뮬레이션 0회.** 첫 달은 대기 없음/있음 4/5회, 월간은 현재 사본 재사용 시 5/6회. 현재 사본 생성이 필요하면 1회 추가하는 기존 규칙도 유지한다. `gridFill`은 기존 시간별 결과를 보정하며 `simulate`를 다시 부르지 않는다.

시험 탄소는 소비 기준으로 비교하도록 `trialCompareHTML`의 상대편도 `co2Cons`로 맞췄다. 자체 생산 탄소를 소비 탄소와 비교하지 않는다.
