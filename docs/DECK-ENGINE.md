# 덱 엔진 자료 형식(설계 초안)

2026-10-10 작성. 2023 확장판 셋(물·인구·감염병, D-70)이 함께 쓰는 '10년 경로 덱' 엔진의 자료 형식이다. **구현은 2022 짝 완성 판정 뒤**에 한다. 이 문서는 덱 자료 파일이 무엇을 담아야 하고, 엔진과 검사가 무엇을 보장해야 하는지만 정한다.

## 1. 설계 목표와 범위

2023 기출의 구조(경로도 + 지수 3개 + 고정 이웃 + 조건부 사건 + 유실 정보)를 코드가 아닌 자료로 표현해, 덱 파일만 바꿔 다른 소재를 돌린다. 충실판 `g2023.js`는 건드리지 않는다. 대신 2023 기출을 이 형식으로 옮긴 '기준 덱'을 검사에만 두고, 엔진 계산이 `g2023.js`의 `compute`와 같은지 대조한다(§6).

엔진이 다루는 것: 해마다 카드 한 장 선택, 선수 조건, 효과 누적, 이웃과의 격차(경계·위험), 판정 연차와 적용 연차가 다른 조건부 사건, 확정 뒤 유실 설명 공개, 순서만 바꿔 보기, 연차 약속, 조건이 바뀐 후속, 면접 질문 생성.
다루지 않는 것: 점수·순위·별점, 경계 횟수 합계, 이웃이 학생 선택에 반응하는 동적 이웃, 비용·예산 같은 추가 자원. 인구 소재처럼 리그 경제 엔진과 잇는 일은 이 엔진 밖의 선택 확장(§7)으로 둔다.

## 2. 파일과 등록

덱 하나는 `decks/<덱 id>.js` 파일 하나다. 외부 스크립트 없이(D-31) 전역에 등록한다.

```js
KCP.decks = KCP.decks || {};
KCP.decks["water-10y"] = { /* §3 형식 */ };
```

JSON이 아니라 JS 객체인 이유는 빌드 없는 정적 앱에서 `fetch` 없이 `<script>`로 읽기 위해서다. 함수는 넣지 않는다(자료만). 계산은 모두 엔진이 한다.

## 3. 덱 객체 형식

```js
{
  schema: 1,                       // 자료 형식 판본
  id: "water-10y",                 // 파일 이름과 같다. 저장 키 kcp:v1:deck:<id>
  title: "물 10년 계획",
  pair: "2023",                    // 짝이 되는 기출 연도
  habits: ["경로 의존", "시점", "상대 격차", "조건부 사건", "유실 정보 추론"],
  role: "리그·은여울강과 다른 점 1~2문장",   // 화면 '역할 구분' 상자
  years: 10,
  indices: [                       // 정확히 3개(schema 1)
    { key: "infra", name: "기반시설", note: "2023의 과학 자리" },
    { key: "life",  name: "주민 삶",  note: "안전한 물·요금" },
    { key: "eco",   name: "하천 생태", note: "" }
  ],
  gap: { warn: 3, danger: 5, grade: "G" },   // 2023 규칙을 옮긴 가정
  self: { name: "…", place: null },          // place: 실제 지역명(선택, §5)
  neighbors: [
    { id: "up", name: "…", place: null, plan: ["1A", "2B", "…"], events: ["drought"] }
    // plan: 카드 id 10개, 경로 조건을 지켜야 한다. events: 이웃에도 적용할 사건 id
  ],
  cards: [
    { id: "1A", stage: 1, name: "누수 점검", eff: [1, 0, 0],
      text: "보이는 설명", lost: "확정 뒤 공개할 설명(선택)",
      prereq: [],                  // 비어 있으면 1단계. 여러 개면 '그중 하나 완료'
      evidence: ["W1"], grade: "G" }   // 효과 숫자의 등급. 근거가 없으면 G
  ],
  events: [
    { id: "drought", name: "가뭄 경보",
      judge: 3, apply: 4,          // 3년 차 누적으로 판정, 4년 차에 적용
      when: { any: [{ index: "infra", op: "<=", value: 0 }, { index: "eco", op: "<=", value: 0 }] },
      effect: { index: "life", delta: -1 },
      text: "사건 서술", evidence: ["W2"], grade: "G" }
  ],
  conditions: [                    // 조건이 바뀐 후속(성찰) 은행
    { id: "late-drought", text: "가뭄 판정이 5년 차로 늦춰진다면",
      patch: { events: { drought: { judge: 5, apply: 6 } } } }
  ],
  questions: [                     // 면접 질문. 틀은 엔진이 학생 계획으로 채운다
    { key: "gap", kind: "worst-gap", text: "{year}년 차 {index}가 {neighbor}보다 {gap} 낮습니다. …" }
  ],
  evidence: [                      // docs/EVIDENCE-2023-DECKS.md 번호와 같다
    { id: "W1", grade: "O", org: "…", title: "…", date: "2025-10-30", url: "…", quote: "…" }
  ]
}
```

사건 조건 `when`은 `any`(하나라도) 또는 `all`(모두)에 비교식 목록을 둔다. 비교 연산은 `<=`, `<`, `>=`, `>`, `==`만 허용한다. 2023 기준 덱으로 옮기면 전염병은 `judge 3, apply 4, any[과학<=0, 환경<=0], 행복 −1`이고 이웃에도 적용한다. 박람회는 `judge 6, apply 7, all[과학>=5, 환경>=3], 행복 +2`이고 학생 나라에만 적용한다.

질문 `kind`는 엔진이 아는 생성 방식만 쓴다: `fixed`(고정 문장), `worst-gap`(가장 큰 격차의 해·지수·이웃), `top-index`(최종 지수 구도), `lead`(가장 크게 앞선 해), `lost`(학생이 고른 유실 카드), `event`(사건 결과), `gap-span`(경계 기간 줄이기). 덱이 엔진에 없는 방식을 쓰면 검사에서 실패한다.

## 4. 엔진이 보장할 것

1. 계산: 해마다 효과를 더하고, 사건은 판정 연차의 누적으로 판정해 적용 연차의 효과에 더한다. 이웃 계산도 같은 함수로 하되 `neighbors[].events`에 있는 사건만 적용한다.
2. 격차: 같은 해 누적이 이웃 어느 쪽보다 `warn` 이상 낮으면 경계, `danger` 이상이면 위험. 표의 칸 색과 질문으로만 드러내고 합계를 내지 않는다(PLAN-2023 §4.1).
3. 정보 공개 순서: `lost`는 그 카드를 실행한 뒤에만, 덱 전체의 유실 설명·예시는 10년 확정 뒤에만 보인다.
4. 연차 약속은 실전 시간 모드에서 끄고 연습 모드에서 켠다(D-70). 약속 연차는 사건 판정 연차와 마지막 해에서 고른다.
5. 순서만 바꿔 보기는 10년 확정 뒤에만 열리고, 선수 조건을 어기는 교환은 이유와 함께 막는다. 학생 계획은 바뀌지 않는다.
6. 화면 문구에 등급 배지: `grade`가 O·O*인 숫자는 출처와 기준연도를 함께, G는 '게임 가정'으로.

## 5. 실제 지역명과 낙인 방지(D-70)

`place`에 실제 지역명을 넣을 수 있다. 넣을 때는 다음을 지킨다.
- 이웃 계획과 지수는 게임 가정(G)이므로 실제 지역의 정책이나 상태로 읽히지 않게, 화면에 '이 지역의 실제 계획이 아닙니다'를 함께 둔다.
- 인구감소·수질·감염병처럼 낙인이 될 수 있는 소재는 원인·구조(지형, 산업 구조, 기후, 인구 이동의 흐름)를 설명하는 문장으로만 쓴다. 지역끼리 순위를 매기거나 '뒤처진', '오염된' 같은 평가어를 지역에 붙이지 않는다.
- 실제 수치는 `evidence`에 있는 것만, 출처·기준연도와 함께 쓴다.
검사는 덱 문자열에 금지 표현 목록(순위어·비하어)이 지역명과 같은 문장에 나오지 않는지 확인한다(목록은 구현 때 정한다).

## 6. 검사(구현 때 함께 만든다)

`tests/model_deck.mjs`가 모든 덱 파일에 대해 다음을 확인한다.
- 형식: id 중복 없음, 카드 효과 길이 3, 선수 카드가 존재하고 자기보다 앞 단계, 1단계에는 선수 없음, 모든 카드가 1단계에서 도달 가능, 사건 연차가 1~10이고 판정 < 적용, `evidence` 번호가 덱 안 목록에 있음, 질문 `kind`가 엔진 목록에 있음.
- 이웃: 계획 10개가 경로 조건을 지키고 중복 없음.
- 계획 공간: 가능한 항목 집합 수, 순서 수, 경계 0 순서 수를 세어 보고한다. 경계 0 순서가 0개이거나 전체의 대부분이면 덱의 긴장 구조가 무너진 것이므로 실패로 본다. 기준은 2023의 350 / 733,780,864 같은 '좁지만 있는 길'이며, 덱마다 실제 값을 기록한다.
- 사건: 판정 결과가 참인 계획과 거짓인 계획이 모두 있다(한쪽만이면 사건이 장식이 된다).
- 기준 덱 대조: 2023 기출을 이 형식으로 옮긴 `tests/decks/g2023-ref.js`로 무작위 계획 다수와 예시 계획(1C→2G→1A→2C→2B→3C→3B→2H→3H→4G, 최종 9/6/10)을 계산해 `g2023.js`의 `compute`와 같은지 확인한다. 계획 공간 수치 49,504·733,780,864·350·341도 재현한다.
- 낙인 방지 문자열 검사(§5).

## 7. 덱 셋의 초안 방향

세 덱은 서로 독립된 확장판이다(D-70). 지수 이름과 사건은 초안이며 덱 설계 때 바꿀 수 있다.

| 덱 | 지수 3개 | 이웃 | 사건 예 | 근거 |
|---|---|---|---|---|
| 물 10년 | 기반시설 · 주민 삶 · 하천 생태 | 상류·하류 시군 | 3년 차 가뭄 단계, 6년 차 하천 행사 또는 녹조 | W1~W4 |
| 인구 10년 | 일자리 · 생활 서비스(돌봄·교육·교통) · 공동체 | 인접 시군 둘 | 학교 통합 검토, 청년 정착 | P1~P2. 리그 경제 엔진과 잇는 시안(population-10y)은 선택 확장으로 남긴다 |
| 감염병 10년(원헬스) | 감시·의료 역량 · 주민 일상 · 생태·환경 건강 | 같은 하천·생활권의 이웃 둘 | 여름철 수인성 감염(D1·D2), 매개모기 주의보(D5·D6), 항생제 내성(D4) | D1~D6 |

감염병 덱은 2023 원문의 전염병("오염된 강물에서 시작")을 일반화하므로 사건 구조를 가장 많이 물려받는다. 숫자는 D1~D6에서 확인한 것만 쓰고, 그 밖의 효과·문턱은 G로 표시한다. 실제 감염병 사례의 지역 수치는 §5 원칙을 따른다.
