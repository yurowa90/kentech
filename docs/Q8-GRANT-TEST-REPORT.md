# Q8 특별교부세 계약 검사 갱신

2026-10-24 · `wip/q8-grant` · Node v24.21.0 / pnpm 11.25.0.

검사 작성·실행은 끝났지만 **현재 구현은 계약 전체를 통과하지 않는다.** 교부세 0 편집기 회귀 12건과 교부세 없는 사건 서랍의 바이트 동일성 1건이 실패한다. 단언을 완화하지 않고 남겼다. 제품 `ui/` 파일, 기존 보고서, 커밋은 건드리지 않았다. 브라우저·네트워크·stash·nice·bots36·T5 전체 실행 없음.

## 바꾼 기존 단언과 이유

`tests/league/test-econ.js`의 종전 283·287·289·290·292행 부근:

- 초과 도시의 음수 예산 → 일반 예산 0과 교부세 잔액을 각각 단언. 폭염 교부세는 일반 예산·기존 초과 부채에 합치지 않는 계약 때문이다.
- 유료 대응 무조건 거절 → 전용 한도 안 대응 승인과 선택 저장을 단언.
- 교부세 때문에 `budget()`이 대응비보다 커야 한다는 조건 → 일반 예산 0에서도 `fundingOf(kind=respond)`로 승인됨을 단언.
- 초과 부채가 얕아져도 유료 대응 거절 → 취소 후 다시 고르는 실제 승인으로 변경.
- 새 건설 무조건 거절 → 대응 4억 + 설비 8억은 공동 한도 10억 초과라 거절, 대응 취소 후 설비 8억은 승인하는 양쪽 경계로 변경.
- 지도 밖 `i=0`은 정규화 때 사라질 수 있어 합법적 태양광 입지로 바꾸고 실제 8억 비용도 단언. 각 변경에 Q8 이유 주석을 달았다. 계절 모드의 기존 계약은 유지했다.

`tests/league/review/41-v5-s1.js`의 서랍 비교:

- 교부세 달에는 정확한 10억 안내 한 줄이 한 번 생기는지 단언한 뒤, 그 줄과 그 줄의 개행·들여쓰기만 제거하고 기존 사건 자료 정규화를 거쳐 과거 `9c14549`와 UTF-8 바이트를 비교한다. 이 검사는 통과한다.
- 교부세 없는 열대야 달은 안내 줄을 제거하거나 공백을 정규화하지 않고 과거 바이트와 그대로 비교한다. 이 검사는 실패한다. 승인된 안내 추가가 0 달의 회귀를 숨기지 않도록 분리했다.

## 구현 담당자에게 남기는 두 문제

1. **교부세 0 편집기 회귀:** 3,936후보 중 **36후보 불일치**, 6도시 × 2가지 0모드의 12사례가 실패한다. 모두 한도를 0.01억 넘긴 상태다. 화성의 기존 계획 22억은 옛 편집기 상한 21.99억에서 거절되지만 새 공통 판정은 유지로 승인한다. 반대로 기존 설비 일부·선로를 철거하고 새 2억 선로를 넣은 10억 계획은 옛 상한 약 12.19억 안인데 새 판정은 추가 자산이라는 이유로 거절한다. 즉 양방향 허용 판단 변화다. 현재 `fundingOf`의 초과 도시 분기(`ui/league-core.js` 190행 부근)와 편집기 어댑터(`ui/league.js` 4738행 부근)가 만나는 지점이다. 계약의 기존 자산 유지 허용과 옛 편집기 공식 보존을 구현에서 함께 다뤄야 한다.
2. **교부세 없는 사건 서랍 바이트 변화:** 열대야 서랍의 첫 차이는 UTF-8 724바이트다. 대응 버튼 `<div class="lg-evopts">` 앞에 새 개행과 공백 8칸이 들어간다. 현재 `evCards`의 교부세 안내 보간식이 빈 문자열이어도 그 줄의 공백은 남는다(`ui/league.js` 3721행 부근). 양수 달만 안내 줄을 허용하는 검사는 통과했고, 0 달의 바이트 단언은 실패 상태로 보존했다.

이 세션은 검사 작성 범위이므로 위 제품 코드는 고치지 않았다. 실제 브라우저 렌더링·클릭·통신은 사용자 금지에 따라 미실행이며, 해당 검증이 통과했다고 보고하지 않는다.
