# 켄텍 연구 기술 트리 구현 명세 v1 (2026-10-05, 총괄)

근거와 수치는 [ECON-TECH.md](ECON-TECH.md)(조사), 사용자 결정: 큰 갈래 = 켄텍 **5대 교육 트랙**(에너지AI · 에너지신소재 · 차세대그리드 · 수소에너지 · 환경·기후기술) + 여섯 번째 갈래 원자핵 에너지. 카드 = 켄텍 대학원 **12대 연구분야**(공식 목록, O). 사용자 요청 "게임적 요소가 더 강하게": 숨은 보정이 아니라 **눈에 보이는 트리·해금·연출·경쟁**.

적용 범위: 리그(멀티·혼자 하기, 계절·달 모드 모두). #build 혼자 하기 샌드박스는 지금 그대로(기존 3종 연구 유지 — 결과 불변).

## T1. 카드 15장(v1)
기존 3종은 갈래 안 카드로 편입한다(효과·id 유지: `bms`, `grid`, `fcst`). 새 12장은 ECON-TECH §3·§7 수치를 그대로 쓰고(교육용 배속 ≤ 1, 근거 등급 표시), 각 카드에 `{id, branch, field(12대 연구분야 이름), name, need, demo, req[], eff, why, grade, sources}`.

- **배타 선택 2쌍**(ECON-TECH §4.1): `ccu` ↔ `h2store`(화석 개조의 길 vs 저장의 길)와 `smr` ↔ `scable` 중 각 쌍에서 하나만 딸 수 있다(선택의 긴장). 화면에 "둘 중 하나" 표시.
- 연구 속도: 리그 달 턴 한 달 = 4주치(`RS.roundSteps` 3 → 4, 한 달 ≈ 4.3주, G). 12달에 15장 중 5~7장만 딸 수 있게 need를 정한다(ECON-TECH §3 값, 연구소 2·대학 1 기준).

## T2. 게임 장치
- **유레카**: 카드마다 조건 하나(예: `tandem` — 태양광 10기 이상 운영, `hvdc` — 연계선 2개 연결, `vpp` — 수요반응 정책 3달 사용, `ccu` — 석탄 발전 운영, `h2store` — 출력제어 발생). 조건을 채운 달에 남은 need의 1/3을 즉시 진척(문명 VI 참고). 알림 "유레카! ○○ 연구가 빨라졌습니다".
- **완료 연출**: 연구 도입 달의 결과 화면 맨 위에 카드 한 장이 뒤집히며 등장(효과 한 줄 + 켄텍 연구분야 이름 + 근거 등급), 0.8초, prefers-reduced-motion이면 정지. 진행자 뉴스 띠에 "평택, HVDC 연계선 개발".
- **해금 설비**: 해금 전에는 건설 도구에 자물쇠와 "○○ 연구 필요".
- **기술 이전·사용료(멀티)**: 다른 도시가 이미 도입한 카드는 '기술 이전'으로 need의 50%만 들여 딸 수 있고, 그동안 원 개발 도시에 달마다 사용료(건설비 단위 0.5억/달, 최대 6달, G)가 간다. 공동 연구: 연계선으로 이어진 두 도시는 같은 카드를 함께 연구할 수 있고(진척 합산), 둘 다 도입. 눈덩이 방지: 사용료 수입은 도시당 월 3억 상한.
- **칭호**: '그리드 개척자'(차세대그리드 3장), '수소 선도 도시'(수소 2장) 등 갈래마다 하나 — 화면 표시와 진행자 순위표 배지. **점수에는 넣지 않는다**(지배 전략·눈덩이 방지).
- **사건 × 기술**: ECON-TECH §4.6 표에서 이미 있는 사건과 맞물리는 것만(폭염 × fcst/vpp 피해 감소, 태풍 × scable 고장 확률 감소, ESS 화재 × nbat 면역 — 미세먼지 계절관리제 × ccu는 과학적 근거가 없어 2026-10-06 삭제: CCU는 CO₂를 줄이지만 계절관리제는 미세먼지 때문에 석탄 출력을 제한한다). 사건 카드에 "○○ 기술이 있으면 피해가 줄어요" 한 줄.

## T3. 상태·계약
- 자료: 새 파일 `ui/tech-data.js` → `KCP.TECH_DATA = { branches, cards, pairs, titles, eureka, params }`(index.html에서 build.js 앞). 숫자마다 grade·note.
- 리그 상태: 팀마다 `research = { queue, prog, stage, adopted[], eureka[], licensedFrom{}, joint{} }`(기존 연구 구조 확장). 공개 상태에 팀별 도입 카드·진행 중 카드·칭호(진척 % 공개 — 경쟁 정보).
- 요청: 기존 연구 요청 형식 유지 + `license`(other, card), `joint`(other, card). 서버(진행자 reduce)가 배타 쌍·선행·예산을 검사.
- 효과는 MODS 훅으로 build.js 시뮬에 전달(B18처럼 리그에서만, MODS 없으면 결과 불변).
- 컴퓨터 도시 AI(ui/league-ai.js): 성향별 연구 선택(신중 → 신소재·AI, 균형 → 그리드·AI, 공격 → 원자핵·그리드), 배타 쌍 규칙 준수.

## T5. 수용 기준
- **v1.1(2026-10-06): 같은 예산 대안 포함.** 기존 네 전략에 재생+저장·연계선 협력·혼합을 추가한다. 도시·씨앗·36달 길이·이웃의 균형 AI를 고정하고, 해당 도시 SMR 전략이 같은 달까지 실제 쓴 누적 건설·연구비를 대안의 투자 한도로 삼는다. 설비·전선·연구 인력·실증비·연구 운영비를 포함하고 실증비는 중복 계산하지 않는다. 연계선은 자기 부담 건설비와 실제 이웃 구매대금까지 한도에 포함한다(판매 수익으로 한도를 늘리지 않는다). 자동 거래의 미래 구매 상한을 예약하되 예약 자체를 지출로 세지 않는다. 분할 불가능한 설비, 입지·재정·협상 제약 때문에 못 쓴 잔액을 공개한다. 상한만 같다고 집행액까지 같다고 부르지 않는다. 재생의 조기 가동과 SMR 공사 12달 차이는 유지한다.
- 계절·달 모드 리그와 #build 결과 불변(기술을 하나도 안 따면 지금과 같다).
- 배타 쌍·선행·예산 검사가 서버에서 막는다. 사용료 상한. 칭호는 점수 불변.
- 전략 봇 전체 집합(연구 몰빵·연구 0·SMR 조기·수소 장주기·같은 예산 재생+저장·연계선 협력·혼합) 36달에서 한 전략이 6도시 모두 1위가 아니다(B16 필수, 공동1위 포함). SMR 1위 ≤ 3도시는 G 희망 목표로만 기록하고 실패 수에 넣지 않는다. 연구 몰빵−연구 0의 평균 점수 차이는 0 초과 15 이하(G, 회귀 검사 유지).
- 콘솔 오류 0, 390px, 44px, 밝음·어두움, KCP.esc, 도시 이름은 자료(D-58).
