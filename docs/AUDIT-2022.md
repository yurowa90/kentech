**판단.** 충실판은 **g2022 기출 재현 하나**로 정한다. 다른 둘은 충실판에 섞지 않는다.

이유
- 2022의 핵심 동작은 '정적인 자료로 자리를 고르고 말로 정당화하는 것'이다. 시간축 운영(#build·섬)은 출제 의도에 없는 층이다. D-50도 "2022 기출에 시뮬 추가(충실도 훼손)"를 기각했다.
- 섬 전력망 24시는 과제 성격이 다르다(급전·차단 분담, 공정성 가중치). 2022와는 '단일 전원·바람이 멈추면' 후속 질문에서만 만난다. 창작 게임(D-30 대표 게임)으로 두고, 2022 성찰에서 '시간축으로 더 해 보기' 링크로 잇는 정도가 맞다.
- #build는 리그와 엔진을 공유한다(`ui/build.js`, 리그가 같은 계산을 씀). 그래서 충실판과 확장판 사이의 **다리**로 쓰는 편이 자연스럽다. 2022의 배치 판단에 시간·날씨·예산을 얹어 보는 연습 섬이다. 묶음 구조는 '충실판(g2022) → 다리(#build 연습 섬, 선택) → 확장판(리그)'이 된다.

반대 의견(검토할 만한 대안)
- '#build에 KENTECH 2022 지도 팩을 넣어 충실판의 Q2 배치를 가져오게 하자'는 안이 있을 수 있다. 연결감은 크다. 그러나 ① 10×10 정사각 격자와 #build의 헥스 격자가 다르다. ② 2022의 비용 단위·생산량은 무차원이고 #build는 MW·억 단위다. 그래서 '같은 지도'라는 인상이 오히려 혼동을 부른다. 하려면 별도 결정(D-번호)과 시안이 필요하다. 짝 완성의 필수 조건으로 두지 않는다.

## 3. 충실판(g2022) 감사 결과와 완성 기준

### 3.1 코드 감사에서 본 충실도·학습 결함

[확인]은 코드를 읽고 계산한 것이다. 브라우저 검사는 이번에 돌리지 않았다.

1. **PR #1 미병합.** [확인] `git merge-base --is-ancestor`: PR #1(`2c5915e`, `55dd88a`)은 HEAD의 조상이 아니다. 지금 화면에는 2번 조건 1~4 누락, '물고기 서식지·어장' 문구, 연습실 규칙 미표시, 2번 예시의 참살이·빛가람 배치 누락이 남아 있다. README도 "보고서 원문과의 전체 대조는 아직 하지 않았습니다"(econ `README.md:107`). `git merge-tree`로 시험 병합하면 PR #1 → HEAD, PR #2 → HEAD 모두 글자 충돌이 없다. 검사로는 확인하지 않았다.
2. **전선 비용 계산이 원문 예시와 어긋난다.** [확인] `supply()`(`g2022.js:166`)는 발전소마다 마을까지 맨해튼 거리를 따로 더한다. 보고서 2번 예시(풍력 12기)를 이 규칙으로 계산하면 전선이 47칸이다. 빛가람의 F1~J1 다섯 기만 봐도 따로 잇기 22칸 대 간선 공유 약 7칸이다(공유 계산은 손 계산이고 [추측] 수준의 근사). PR #1은 "전선을 함께 쓰면 더 짧아질 수 있음"이라는 주석만 달았다. 2번이 "수학적 사고력"을 보는 문항이라 이 차이는 학습 결함이다. 고치려면 학생이 전선 경로를 직접 긋는 조작(공유 허용)이 필요하다. 이는 저장 형식·계산 변경이므로 새 D-번호와 사용자 확인 사항이다.
3. **'평균 발전 비용'의 해석.** [확인] 게임은 발전소 1기당 15·2를 더한다(`supply`). [추측] 원문이 기당 비용인지 전력량당 비용인지는 저장소로 판정할 수 없다. 전력량당이라면 화석 1기는 900, 풍력 1기는 40으로, 전선 비용의 상대적 무게가 완전히 달라진다. PR #1 대조자도 이 점은 언급하지 않았다. 보고서 원문 확인이 필요하고, 확인 전에는 '재구성(기당 비용으로 셈)' 표시를 붙이는 것이 안전하다.
4. **시간.** [확인] 실전 모드는 30+25다. ROADMAP의 15분 표기는 오류다(§1).
5. **면접실 장면이 1번·2번 중 하나만 보여 준다.** [확인] `ui/stage-2022.js:563`은 면접실에서 `st.mode`(마지막으로 연 탭)의 계획만 그린다. 질문은 1번 → 2번 순서로 나오므로, 질문에 맞춰 장면을 바꾸면 '근거 설명' 단계가 좋아진다. 정답 노출과는 무관하다.
6. **장면의 지도 자료는 사본이다.** [확인] `ui/stage-2022.js:15-40`이 `g2022.js`의 지형·지형지물을 복사해 둔다. PR #1은 지도 값을 바꾸지 않았으므로(D-44 기록) 지금은 일치한다. 이후 원문 확인으로 지도가 바뀌면 두 곳을 고쳐야 한다. 2024처럼 화면에서 읽게 하거나 한 곳에서 내보내면 위험이 없어진다.
7. **VISION 제안 10의 '조건 바뀐 후속 → 계획 한 줄 수정'이 없다.** [확인] `g2022.js`에 해당 장치가 없다. 2022 출제 의도("추가 질문으로 사고 확장")와 바로 맞닿는 성찰 장치다.
8. **접근성 의심.** [추측, 코드 읽기만] 지도는 `role="grid"`인데 행·셀 역할이 없고(`g2022.js:180`) 칸 100개가 모두 탭 정지점이다. 화살표 이동(roving tabindex)과 올바른 역할이 필요해 보인다. axe나 화면 낭독기로 확인해야 한다. 색 대비는 PR #4 검사 범위였다.
9. **보고서 문항과 연습용 질문의 구분은 지켜지고 있다.** [확인] `src:"report"`는 두 개이고, 나머지는 태그로 구분된다(`tests/accept_base.py`의 REPORT_KEYS 계약, PR #1 설명).

### 3.3 확장판(리그)과 이어지는 지점

- **용어.** 2022는 발전 설비, 마을, 전선, 공급 필요량, 영향 분석(미세먼지·해류)을 쓴다. 리그는 설비, 도시·집단, 송전·연계선, 수요, 민원 렌즈·접속 여유를 쓴다. 대응표를 하나 두고, 리그 S2(배치 판단) 도움말에 '2022에서는 이것을 ○○라고 불렀다'를 한 줄 넣는 정도가 적당하다.
- **질문 은행.** 이미 대응표가 있다(`docs/ECON-INTERVIEW.md:33`, `:102-123`): lg-c-site↔22-q1, lg-i-smoke↔22-q1-fos, lg-f-typhoon↔22-div-typhoon, lg-h-approval↔22-hum-future. 화면에서 이 연결을 드러내는 장치는 아직 없다([확인] `ui/league.js`에서 '기출'·'2022' 검색 결과 없음).
- **화면.** 홈에는 #build·#league가 '시안' 링크로만 있다(`ui/v2.js:226-227`). ROADMAP의 '2022 확장판 · 전력 리그' 카드는 아직 없다(S1·시안 C 담당).
- **데이터.** 2022는 무차원 가상 수치이고, 리그는 근거 대장(ECON-REFERENCES) 기반 실제 단위다. 데이터를 공유하지 말고 **사고 동작을 공유한다**는 원칙을 문서에 적는다. 그래야 '같은 숫자'라는 오해를 막을 수 있다.
- **되돌아가는 연결.** ROADMAP 완성 기준 3의 '확장판 안에서 충실판의 사고 습관으로 돌아가는 연결'을 구현할 후보는 둘이다. ① 리그 끝 성찰에서 '2022 미션 켄텍으로 30+25 연습' 링크. ② VISION의 '구조 도감' 중 '2022 공급과 전선 비용' 카드. ①은 작고, ②는 큰 기능이라 시안을 비교한 뒤 정한다.
