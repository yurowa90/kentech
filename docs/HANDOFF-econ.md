## 3. 설계 SPEC(요약 — 원문 docs/ECON-SPEC.md, 자료 docs/ECON-DATA.md)
1. 시간: 1턴 = 1달(12/24/36턴, 로비에서 고름, 기본 12). 1월마다 재정지원금. 달마다 대표 7일 전력 운영을 달 일수/7배로 환산.
2. 도시 상태: pop(주민, 실제 규모), ind(종사자), cash(에너지·산업 계정, 음수면 지방채, 한도 연 세입 50%), 세율 단계 taxRes·taxInd(−2..+2), 공공서비스 단계, 기업 보조.
3. 살기 좋음 L: 전력 신뢰, 전기요금, 대기질, 일자리, 공공서비스·교육(대학), 세금, 혼잡. 산업 매력 A: 전력 신뢰(큼), 단가, 재생 비중(RE100), 인력, 대학, 물류(항만), 세율, 보조, 용지.
4. 이동: 목표 몫 s* = 현재 몫 × exp(β·(L−L̄)/10) 정규화, 달마다 κ만큼 다가감(주민 0.01, 산업 0.005). 합 보존. 기업 이전 희망 사건(조건 제시 → 도시 제안 → 진행자 결정).
5. 재정: 세입 = 재정지원금(기본 + 1인당 + 재정자립도 균형분) + 주민세 + 산업세 × 산출 지수 + 전력 거래. 세출 = 건설·연료·운영·서비스·보조·이자.
6. 순환 고리: pop·ind 배수만큼 마을·산업 전력 수요가 바뀜(build.js `MODS.demandRes`, `MODS.demandInd` — 이미 구현).
7. 국제: LNG 가격·환율·수출 수요·해운 지수(씨앗 난수, 평균 회귀), 사건(해운 차질, LNG 급등, 수출 호황, EU CBAM — 철강 수출 도시 감점), 연료비 배수 `MODS.fuelMul`(이미 구현).
8. Democracy: 정책 슬라이더, 지연 효과(달마다 25%), 집단 6개(직장인·청년·노년·기업·농어민·환경단체) 만족 → 지지율, 12턴마다 평가.
9. 점수: 주민·산업 증가, 현금, 1인당 CO₂, 지지율, 정전 → 0–100 가중 합, 순위표.

## 4. 진행 상황(이 브랜치, 2026-10-03 클라우드 세션 기준)
끝남

알려진 문제(다음 담당이 먼저 볼 것)
1. 정전 100%인 도시도 지지율이 거의 안 떨어지고(12달 동안 53→56) 인구 감소가 연 1% 미만 — 화면에서 원인·결과가 안 보인다. 반대로 자료 조사는 지금 β가 현실보다 3~4배 빠르다고 함(β_pop ≈ 0.08 권장). '현실 속도'와 '수업에서 보이는 속도'를 나눠 정할 것(예: 현실 계수 × 교육용 배속, 화면에 배속 표시).
2. 점수에서 현금 부분이 '쓰지 않고 쌓기'를 보상한다(투자 안 한 당진이 한때 평택보다 높음). 현금은 부채 감점만, 또는 '투자 효율'로 바꿀 것.
3. 달마다 순수입이 커서(도시당 월 +30~60억) 1년이면 시작 예산의 2배 — 타이쿤 성장감은 좋지만 연계선·연구 비용 대비 너무 쉬울 수 있음. 밸런스 실행으로 확인.
4. 사건이 매달 1~2개 나오는 빈도(계절 라운드 기준)를 달 턴에 맞게 낮출 것.
5. 독립 검토(Opus)가 클라우드 세션에서 진행 중이었다 — 결과는 이 문서 끝 '독립 검토 결과'에 덧붙여 올린다(없으면 맥에서 다시 돌릴 것).

## 7. 독립 검토 결과(Opus, 맥락 없이 처음부터, 2026-10-03)
다시 돌리기: `cd tests/league/review && node 1-invariants.js` … `node 8-offers.js`(입력은 lib.js의 근사값 — 5·6번 결론은 실제 호스트 입력 `econInput`으로 다시 확인할 것).

정확성: 통과 — 40씨앗 × 36달 + 극단값, 2,330,048개 검사 실패 0(총량 보존·성장식·현금 항등식·결정성·NaN 없음·0–100·재정지원금 3회). 단, league-core `econMonth`가 monthStep 뒤에 현금을 따로 바꿔(사건 지원금·철거 회수) 보고서 cashAfter ≠ 다음 달 cashBefore.

치명
1. 세율·서비스 지배 전략: 모든 경우 '세율 −2 / 서비스 +2'가 1등. 주민세 ±2단계 차이(월 2.8억)가 전기요금 수입(121억)·운영비(112억)에 묻힘 → 주민세 단가 약 3배, svcStep 0.5, 전기요금 수입은 차익만 또는 따로 표시. 목표: '세율 −2·서비스 +2면 적자'.
2. 기업 이전 희망은 같은 조건이면 늘 화성: 순위에 상쇄 전 매력 `C.A`(인구 로그·대학 수 포함)를 씀. 안성은 보조 20억·산업세 −2·재생 100%로도 못 넘음. spareMW가 안 넘어와 MW 조건 무시 → 순위를 '시작 대비 개선폭(Aeff)'이나 공개 입찰로, MW 정보 없으면 불충족 처리.

중요
3. 지지율 평가가 사실상 꺼짐: 정전 5%·세율 +2·서비스 −2·재생 0에도 45–50 → 목표 = 55 + 1.5·(목표 − 시작 목표), 또는 기준 '시작 지지율 − 10'.
4. 전기요금 수입(tariff)이 SPEC에 없는데 현금 흐름을 지배 → SPEC 반영 또는 지역 평균 대비 차익만.
5. 전기 판매 이중 이득: costPerMWh에 거래 수지가 들어가 0 이하 → 전기요금 점수 100(아산 +1.54%) → 주민 요금 계산에서 거래 제외, 하한(평균 × 0.5), 모든 도시를 평균에 포함.
6. fiscalNorm 배수(화성·천안 0.57, 당진 1.72)로 같은 주민 1만 명의 세금 가치가 3배 차이 → 세율 단가는 같게, 차이는 도시별 정액 보정 지원금으로.
7. 정전 효과가 크고 회복이 없음(평택 정전 5% 12달 → −4.6%, 36달에도 −6%) → 목표 몫에 시작 몫 20% 섞기(w = 0.8·지금 + 0.2·시작).
8. 지방채 한도가 거래 한 달에 155 → 3155 → 155로 출렁이고, 호스트 budget()이 현금만 봐서 지방채 규칙이 작동하지 않음 → 한도 = 거래 뺀 최근 12달 세입.

사소: yearStart 중복 지급 가드 없음(paidYear), 작은 흐름에도 원인 뉴스(문턱 필요), capexMul 미사용, E.len 무시(12턴인데 40턴까지 돎), L0·A0 미사용, params 밖 매직 넘버 다수(107, 119–125, 140–142, 149–150, 254, 264, 389, 396, 368, 97행), SPEC 4절에 anchor 0.9 누락.

문제 아님(확인함): 아무것도 안 하면 36달 흐름 0.6% 미만, 안성도 최선 정책이면 1등 가능, 막판 세금 올리기는 손해, 폭주 없음(단 혼잡 감점 약함 — 한 도시만 좋으면 36달에 1.5배).

리드 판단(클라우드): 1·2·3·5는 다음 담당이 먼저 고칠 것. 정전 반응은 '지지율은 약함(3번), 인구는 강함(7번)'으로 갈려 있어 두 축을 함께 맞춰야 한다 — 자료 조사(ECON-DATA)는 현실 이주 속도가 지금의 1/3~1/4라고 하므로, 인구 β는 낮추고 지지율·뉴스로 원인을 보이게 하는 쪽을 권한다.
