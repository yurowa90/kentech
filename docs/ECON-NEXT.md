# 리그 개선 명세 v1 — 감사 + 영상 피드백 통합 (2026-10-05, 총괄)

근거: 7개 점검 항목 감사(검사 7 + 반박 검증 7 + PM 종합, 판정: 사회적 쟁점 '부족', 나머지 6개 '부분'), 사용자가 전달한 영상 피드백(진행자 2분 22초·평택 2분 11초), 결정 D-60~D-63. 순서는 피드백 권고대로 ① 표시 정합성 → ② 원인 설명 → ③ 짧은 예측·수정 → ④ 공동목표·기여 → ⑤ 화면 정리.

## 0. 필드 약속(묶음 사이 계약 — 이름 그대로)
- `publicView(S).teams[id].left` = 이 팀이 지금 쓸 수 있는 돈(= budget − 계획 지출 spendOf). 진행자·팀 화면 모두 '남은 돈'으로 이 값만 쓴다. `budget`은 내부값으로만.
- `res.team[id].ledger` = `{ open, income, invest, opex, close }`(억, 기초 잔액 + 지원금·수입 − 신규 투자·운영비 = 기말 잔액, 항등식 0.01 이내). 화면 이름 '이번 턴 총지출' = invest + opex.
- `res.team[id].loss` 송전 손실 MWh, `res.team[id].idle` 선 없는(미연결) 설비 출력 MWh, `res.team[id].cpList` = 민원 목록 `[{ kind: "noise"|"view"|"smoke"|"forest", score, near }]`.
- 엔진 원인: `report.cities[id].causes` = 이번 달 변화 기여가 큰 순 `[{ key, label, delta }]`(최대 3, 정전 감점·병원 정전 감점·민원은 각각 별도 key), `report.groups[id].why`는 `causes[0]`과 같은 key를 쓴다.
- 시험 운전 보정값: `KCP.leagueCore.trialMods(S, R, id)` → 그 달 실제 운영과 같은 mods(접속 대기 reCap, 출력제어 curtailP, essCap, 수요·연료 배수, 도입 기술) — **사건 효과와 실제 크기 ev.x는 넣지 않는다**(누출 방지). build.js mount 옵션 `leagueMods(st) → mods`.
- 공동목표·기여: `report.region = { unsPct, co2, goal: { uns, co2 }, met: { uns, co2 } }`, `report.contrib[id] = { exportMWh, importMWh, co2Cut, tieCost }`, 보너스 `params.coopBonus`(G) — `score(E)`의 parts에 `coop`가 아니라 총점에 더하는 작은 값(parts 6개 계약 유지, `by[id].coop` 별도 필드).
- 표시 기준: 결과 화면 머리에 '○월 결과 · 다음 운영 ○월'. 지표 이름에 기준을 붙인다: 'CO₂(이번 달 운영)', '민원(지금 지도 기준)', '정전(이번 달)'.

## 2. 팀 화면 묶음(Sol) — ui/league.js(결과 탭·진행자 화면 제외 — 3·5 묶음), ui/league.css, tests/league/econui.py·solo.py·e2e3.py
- 피드백 ①: 상단 HUD·팀 서랍의 돈을 `left`로 통일, '현금'·'지방채 한도'는 따로, 지표 이름에 기준.
- 감사 C: lg-c-site 발동 조건(실제 새 건설비 ≥ 예산 20%), 고치겠다/유지 버튼은 r·p·f형만, 분기 달 질문 하나, 사건 대응 버튼도 '기준 먼저' 관문(n.big), 사건 달 반문은 lg-f-event, 다음 달 일지 맨 위에 지난달 반문 답·'다음에 바꿀 것', lg-i-smoke 조건, 활동지에 건설 일지.
- 피드백 ③: 핵심 고리 '근거 데이터 하나 고르기(칩: 저녁 수요·접속 여유·연료비·이웃 정전 등) → 결과 방향 예측 → 실제와 비교 → 유지/수정'. 한 문장 설명은 첫 전략과 큰 변경 때만. 자유 실험(혼자 하기)에서는 건너뛰기 허용, 학습 미션 달성은 고리 수행과 연결.
- 감사 A 화면부: 디브리핑 카드는 공개 상태로 전제 확인 뒤에만, 끝 요약 이주 흐름, 조사(이/가·을/를) 함수.
- 감사 F 표지부: '시작값: 공식 통계' 일괄 표지 제거 → start.src 표시, '억 = 게임 단위', 지수 '1 = 2026년 수준 · 가상 변동(G)', 사건 등급 E.grade, D-60 한 줄 선언.
- 감사 G: 혼자 하기 '처음부터' 확인 창, 끝 화면 '같은 조건으로 다시', 지난 판 대비 비교.
- U5 결함: 관전 화면에서 `#lg-peek`·`#lg-peek-region`·`#lg-peek-back`·`#lg-ready`가 둘 이상 생긴다(모바일 390에서 peek.py 실패) — id 중복 제거.
- 피드백 ⑥ 학생 쪽: 막대 버튼과 서랍 탭 중복 정리(한 군데로), 서랍이 지도를 덜 가리게(접기·폭), 기본 지도는 주요 거점만, 송전 작업 중에 연결 상태 강조('선 없음' 표지는 송전 도구 때만).

## 3. 결과 탭·진행자 묶음(Sol, 2 다음) — ui/league.js 결과 탭·진행자 화면
- 결과 탭: '○월 결과 · 다음 운영 ○월', 정전 %p·정전 시간(outH)·CO₂의 지난달 대비 Δ, 원인(causes) 한 줄, '시험 / 실제 / 차이 원인(사건·이웃 거래·접속 대기·날씨)', '자리 탓' 한 줄(loss·idle·접속 대기), 장부 한 줄(ledger), '이번 턴 총지출', CO₂ 변화가 선택 때문인지 계절·수요 때문인지 구분(같은 계획 기준 수요 배수 대비).
- 공동목표·기여(D-61): 지역 공동성과 / 도시별 기여 / 도시 자체 성과 세 단, 공동 보너스 표시, 이주 유입의 편익과 부담(수요 증가·서비스 비용) 한 줄.
- 진행자 첫 화면(피드백 ⑥): 현재 턴·남은 시간·준비 완료 팀 수·미준비 도시·지역 공동목표·위험 도시를 한 줄 판에, 여섯 도시 요약표(정전·CO₂·현금·지지율·주민 Δ·준비)를 지도보다 위에, 상세 지도·도시 카드는 접어 두고 도시를 누르면 연다.
