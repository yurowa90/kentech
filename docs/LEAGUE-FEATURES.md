## 판정과 읽는 법

- **핵심**: S1~S8의 확인·조작·기록·비교를 직접 수행하는 화면. 화면을 접더라도 접근 경로는 남겨야 한다.
- **보조**: 해당 장면의 판단을 돕거나 참가·접속·교사 운영·수업 정리에 필요한 화면. 매달 기본 화면에 모두 펼칠 필요는 없다.
- **보류 후보**: 장면과 연결이 약하거나, 같은 일을 다른 경로로 반복하게 하거나, 화면 복잡도가 큰 부분. 아래 여섯 묶음만 제안한다. 확정 규칙을 폐기한다는 뜻은 아니다.
- 열의 `목표`는 CANON의 학습 목표 번호다. `지원`·`확장`은 직접 장면이 아니라 간접 연결이다. 해당 번호는 코드에 붙어 있는 태그가 아니라 이 분류의 판단이다.
- 위치는 저장소 기준 `파일:함수`다. 표의 검사 파일명은 모두 `tests/league/` 아래다. **직접 단언**은 화면 요소·내용·조작을 검증하는 코드, **경로 사용**은 검사 실행이 그 버튼 등을 거치는 것, **규칙 검사**는 화면을 숨겨도 남아야 하는 엔진 계약을 뜻한다. `직접 단언 미발견`은 읽은 검사에서 못 찾았다는 뜻이며 검사 전체 부재를 보장하지 않는다.
- 마지막 열은 향후 보류할 때의 영향 분석이다. 이 작업에서 숨기거나 검사를 수정하지 않았다. 기존 검사 소스의 존재를 확인했으며, 실행 통과를 주장하지 않는다.

**누락 의심/현재 구현의 경계**

1. **QR 참가**: README와 진행자 문구에 QR 안내가 있지만 `league.js`에 QR 생성·표시·버튼이 없고 지정 화면 코드에서도 발견하지 못했다. J01은 코드/링크 참가로만 집계했다. 별도 QR 제공 경로가 있다면 추가 목록 필요.
2. **실제 운영의 마을별 정전 색/시간별 재생**: `paintLeagueLayers`는 `actual.town`이 있을 때 칠할 수 있지만, 현재 `league-core.js:run`이 만드는 팀 결과에는 `town` 배열이 없다. 현재 경로는 실제 월 요약·민원 영향 핀·도시 정전 테두리이며, 수요지별 칠/최대 부족은 로컬 **시험** 결과다. 구현된 기능을 ‘실제 마을별 정전 지도/대표일 재생’까지 확대해서 쓰지 않았다. 새로운 결과 배열 전송은 단순 숨김/표시와 다른 작업이다.
3. **연구 큐 수정의 중복 경로**: 리그 15장 상세는 ‘연구 순서에 넣기’이며 이미 큐에 든 카드에는 이 버튼이 비활성이다. 옛 건설 연구 UI는 눌러 큐에서 뺄 수 있다. G11을 숨기기 전에 취소/재정렬 기능이 필요한지 결정해야 한다. 두 경로의 단계 문구/예상 계산 일치도 이번에는 실행 검증하지 않았다.
4. **끝 타임라인의 변경 범위**: 설비/전선은 개수(`n`,`l`) 변경으로 표시하므로 같은 개수의 위치 교체를 모두 기록하지 않는다. 정책 변경 표시는 자기 기기의 월 메모에서 읽으며 모든 도시 정책·세부 결정 전체 이력은 아니다. 해당 한계 때문에 I02는 ‘모든 결정의 인과 기록’이 아닌 보조 자료로 분류했다.
5. **시험 HUD→실제 결과 서랍**: HUD 라벨은 ‘CO₂ 시험’인데 바로가기는 `result`로 연결되어 지난 실제 월 결과를 열 수 있다. 과거 검토의 기준 혼동과 관련된 정적 연결이 남아 있다. B09의 분류가 현재 의미 일치를 보장하지는 않는다.
6. **교사 안내 2쪽·학생 활동지 1쪽·익명 사전/사후 5문항**: BENCHMARK §5의 수업 꾸러미 제안이다. 리그 화면에는 수업 시간·CSV·활동지 **글 복사**가 있으나, 위 별도 문서/설문 화면은 지정 코드에서 발견하지 못했다. 복사 기능을 인쇄용 활동지/설문 구현으로 집계하지 않았다.
7. **미구현 제안 제외**: CANON/BENCHMARK의 송전 회랑·정의 장부·짝 청문 무대·집단 요구/최후통첩·교사 질문 보내기/사건 직접 내기·예측 방향 집계·반사실 비교·프로젝터 전용 모드는 읽은 화면 코드에 구현 경로가 없어 분류 수에 넣지 않았다. 진행자 기본판이 프로젝터에 쓰인다는 설명과 전용 모드는 구별했다.
8. **검사/시연용 API 제외**: `KCP.league.state/next/plan/uiMath`, `buildGame` 계산 API, 서명·재전송 자체는 학생 화면 버튼이 아니다. 사용자에게 보이는 대기/거절/복구 안내는 A·B·J에 포함했다. 그림의 나무·물결 등은 C12 장면 연출에 묶었고 독립 교육 기능으로 세지 않았다.

**독립 검토와 현재 코드의 구분**

`review-result.json`은 이전 화면 묶음의 재현/반박 결과이며 현재 커밋의 실패 목록으로 그대로 옮기지 않았다. 현재 코드에서 월 이력 `t+1`, CSV 연/월, 시험 접두어/최대·평균 구분, 원인 층 중복 축소, 렌즈 선택 기억/다른 색, 첫 시험 성적표 유지, 약속 카드 포커스, 자료 도움말 경로, 서랍 스크롤 초기화, 수업 시간 배분, 계절 TIP 필터, 지방채 출처 수정 경로를 확인했다. 확인은 **코드 대조**이며 모든 viewport·테마에서 결함이 해소됐다는 실행 결과는 아니다. 민원 핀은 ‘민원 건수’와 ‘영향 마을 수’를 따로 표기하며 여전히 `score > 0`인 영향 마을을 가리킨다.

반박된 ‘철거 손실을 결과 현금 장부에 다시 넣어야 한다’는 제안을 분류 근거로 채택하지 않았다. C08의 철거 손실(매몰 비용)과 F07의 현금 등식을 구분한다. 풍속 칩도 실제 관측 예보로 승격하지 않고 현재 코드의 ‘계절 대표값·높이 환산, G’로 기록했다.

**작업 경계 확인**: 종료 대조에서 기준 문서·화면 코드·검사 파일에 미커밋 diff가 없음을 확인했다. 작업 중 별도 `docs/PROGRESS.md` 변경이 관찰됐으며 이 작업에서는 해당 파일을 쓰거나 되돌리지 않았다.

**실제 검증 범위**: 파일/함수·화면 템플릿·라우트·이벤트 연결·CSS 숨김 조건·관련 검사 단언을 정적으로 대조했다. 게임 코드를 수정하지 않았고, 브라우저 수업 시연·온라인 연결·전체 회귀/밸런스 검사는 실행하지 않았다. 산출물만 작성하므로 앱 변경용 테스트를 새로 만들지 않았다. 기능 분류와 보류 여부는 CANON에도 사용자 결정 사항으로 남아 있다.
