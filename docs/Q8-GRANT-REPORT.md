기준: 2026-10-24, `wip/q8-grant`, 변경 전 `228856b`. Node v24.21.0, pnpm 11.25.0. 저장소에 package.json·lockfile·Node 버전 파일 없음. 외부 네트워크·브라우저·커밋·stash·nice 실행 없음. 법령은 총괄 제공 근거를 사용했고 외부 원문을 재열람하지 않았다.

- `ui/league-core.js`: `bonusOf`, `budget`, 새 `grantAmount`·`grantOf`·`fundedSpendOf`, `reduce`의 plan/respond/research/tie 가용액 검사, `advanceResearchAll`, `run`·`econInput`·`econMonth`의 실제 사용액 전달. 추첨·급전·AI 규칙은 변경하지 않았다.

## 지급·정산과 제한

월 모드에서 기존 추첨 사건이 `scopeHits`로 도시에 해당하면 사건당 10억을 사용 한도로 부여한다. 별도 사건을 추가하거나 난수를 소비하지 않는다. 옛 계절 모드는 보존한다. 사용액은 `min(교부 한도, 월초 base에 없던 현재 설비·도시 안 선로의 총비용 + 이번 달 사건 대응비)`다. 승인된 대응비를 공유 한도에 포함하며, 기존 자산·철거 손실·연계선·연구 실증/사용료·운영비는 적격 비용에서 제외한다. 여러 재난 사건이 같은 달에 있으면 해당 사건별 한도를 합산한다.

`budget`에는 계획용 교부 한도를 더하되, 한도 초과 도시의 기존 부채를 이 돈으로 메우지 않는다. 새 건설·유료 대응의 누적 적격 비용이 한도 안인지 별도로 확인한다. 변경/취소 때 현재 계획·대응을 다시 계산하므로 요청 분할이나 철거 회수로 한도가 늘지 않는다. 연계선 수락의 기존 `debt:` 거절은 유지한다. 한도 안인 도시도 미사용 교부세를 연계선·연구에 쓰지 못하도록 별도 예약액으로 제외한다.

현금으로 교부 전액을 선지급하지 않는다. `run`에서 월초 자산을 갱신하기 전에 사용액을 지역 변수로 저장하고, `econInput`이 `기존 일반 사건 지원금 + 특별교부세 실제 사용액`만 energy.bonus로 넘긴다. 미사용액은 세입에 들지 않고 월말 소멸하므로 운영 적자나 다음 달 현금에 쓰이지 않는다. 경제 엔진의 `cashBefore + revTotal − expTotal = cashAfter`는 그대로이며, 실제 9억 사용·0억 사용 두 정산 사례에서 오차 1e-9 미만으로 확인했다. 표시 장부는 기존 0.001억 반올림으로 검사했다.

법령은 특별교부세 제도·용도 제한의 근거다. 자동 교부, 금액, 사건 대상 판정, 지방채 초과 도시의 게임 내 좁은 건설 예외는 게임 가정이며 실제 지방채 법제의 예외를 재현한 것으로 해석하지 않는다.

## 전송 계약

팀 요청 형식과 publicView의 필드 목록을 바꾸지 않았다. 지급·사용·소멸액은 기존 공개 사건 id·round, base·plan·resp와 배포 자료에서 결정적으로 계산한다. 월말 사용액 전달은 함수의 지역 인수이고 저장/전송 필드가 아니다. 기존 `budget`, `left`, `rev.bonus`의 숫자만 달라진다. 변경 전후 공개 상태의 재귀 필드 모양이 동일함을 Node에서 대조했다. 새 전송값·새 공개 필드 없음(D-65).

## 최종 상태 — 독립 검토 major·minor 반영 (2026-10-24)

앞 절은 각 구현 당시의 측정 기록이다. 아래 내용이 현재 구현을 설명한다. `fundedSpendOf`는 최초 구현의 옛 이름이며 현재 공개 자금 판정 API는 `fundingOf`다. 당시의 ‘budget에 교부 한도를 더한다’, ‘build.js 수정 없음’, 실패 수를 최종 상태로 읽지 않는다.

- 팀 계획 HUD와 도시 서랍은 일반 잔액과 남은 특별교부세를 확정 문구 `남은 돈 {n}억 (빚 한도 포함) · 이번 달 특별교부세 {m}억(새 설비·선로·재난 대응만)`로 표시한다. 전용 잔액 0이면 종전 문구·DOM을 유지한다. HUD 주석에는 0인 달에 `data-money-note`를 붙이지 않고, 전용 잔액이 있으면 기존 줄바꿈 클래스 `lg-tipbody`를 쓴다. 라벨용 `v2-cap-k`를 주석에 사용하지 않는다. 도시 서랍의 `<p class="lg-left">`는 교부세가 있을 때 title만 추가하며 aria-label은 붙이지 않는다. 진행자 팀 줄은 변경하지 않았다.
- 편집기의 `budget(plan)` 콜백은 호스트와 같은 `fundingOf`를 호출한다. 설비 배치·선로 미리보기·확정은 반환값의 `ok`로 판단한다. `ui/build.js`의 일반 예산 표시에서 교부세 잔액 합산을 제거하고, 지도 aria-label과 돈 값 title에는 같은 확정 문구의 일반 잔액·교부세 잔액을 나눠 넣었다. 수치는 기존 각 화면의 자리수 규칙을 따른다. 새 CSS·공개 필드는 추가하지 않았다.
- `budget()`의 경제 모드 공식은 항상 `cash + debtCap + unpaid − grant + committed + tieAt − tieShare`다. 교부세 달의 `headroom=0` 처리를 제거했다. 화성이 지방채 한도를 100억 초과하고 기존 태양광 3기 중 2기를 철거하면서 grid 실증비 4억을 예약하면, 사건 없는 달과 폭염 달 모두 일반 예산 −76억·예약 후 잔액 −99.2억으로 같고 거절된다. 호스트·공개 snapshot·실제 편집기 후보 판정·reduce에서 거절을 확인했다.
- `grantOf()`의 대응비는 이번 달 `E.grant`가 있는 교부 대상 재난 사건만 적격이다. 총 대응비 장부는 유지한다. `fundingOf`의 초과 도시 대응 예외에도 같은 범위 검사를 넣어, 적격 비용에서 빠진 비재난 대응이 오히려 예외를 통과하지 않게 했다. 폭염과 열대야가 함께 있는 가상 상태에서 열대야 대응비 3억은 교부세 사용 0억이며, 초과 도시는 거절·일반 예산 50억 도시는 승인된다. 실제 사건 추첨 규칙은 바꾸지 않았다.
- AI 추가 수정은 필요하지 않았다. `econ.debtStage`는 한도 초과 시 `crisis`이고, 기존 AI는 건설 예산 탐색 전에 반환하며 연구도 `ok` 이외 단계에서 반환한다. 따라서 제거한 바닥값을 사용하는 초과 도시 탐색 경로가 없다. 기존 미커밋 AI 변경은 그대로 보존했다. 후보 승인 함수는 계속 `fundingOf`다.
