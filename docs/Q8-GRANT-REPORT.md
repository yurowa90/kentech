## 지급·정산과 제한

월 모드에서 기존 추첨 사건이 `scopeHits`로 도시에 해당하면 사건당 10억을 사용 한도로 부여한다. 별도 사건을 추가하거나 난수를 소비하지 않는다. 옛 계절 모드는 보존한다. 사용액은 `min(교부 한도, 월초 base에 없던 현재 설비·도시 안 선로의 총비용 + 이번 달 사건 대응비)`다. 승인된 대응비를 공유 한도에 포함하며, 기존 자산·철거 손실·연계선·연구 실증/사용료·운영비는 적격 비용에서 제외한다. 여러 재난 사건이 같은 달에 있으면 해당 사건별 한도를 합산한다.

`budget`에는 계획용 교부 한도를 더하되, 한도 초과 도시의 기존 부채를 이 돈으로 메우지 않는다. 새 건설·유료 대응의 누적 적격 비용이 한도 안인지 별도로 확인한다. 변경/취소 때 현재 계획·대응을 다시 계산하므로 요청 분할이나 철거 회수로 한도가 늘지 않는다. 연계선 수락의 기존 `debt:` 거절은 유지한다. 한도 안인 도시도 미사용 교부세를 연계선·연구에 쓰지 못하도록 별도 예약액으로 제외한다.

현금으로 교부 전액을 선지급하지 않는다. `run`에서 월초 자산을 갱신하기 전에 사용액을 지역 변수로 저장하고, `econInput`이 `기존 일반 사건 지원금 + 특별교부세 실제 사용액`만 energy.bonus로 넘긴다. 미사용액은 세입에 들지 않고 월말 소멸하므로 운영 적자나 다음 달 현금에 쓰이지 않는다. 경제 엔진의 `cashBefore + revTotal − expTotal = cashAfter`는 그대로이며, 실제 9억 사용·0억 사용 두 정산 사례에서 오차 1e-9 미만으로 확인했다. 표시 장부는 기존 0.001억 반올림으로 검사했다.

법령은 특별교부세 제도·용도 제한의 근거다. 자동 교부, 금액, 사건 대상 판정, 지방채 초과 도시의 게임 내 좁은 건설 예외는 게임 가정이며 실제 지방채 법제의 예외를 재현한 것으로 해석하지 않는다.

## 전송 계약

팀 요청 형식과 publicView의 필드 목록을 바꾸지 않았다. 지급·사용·소멸액은 기존 공개 사건 id·round, base·plan·resp와 배포 자료에서 결정적으로 계산한다. 월말 사용액 전달은 함수의 지역 인수이고 저장/전송 필드가 아니다. 기존 `budget`, `left`, `rev.bonus`의 숫자만 달라진다. 변경 전후 공개 상태의 재귀 필드 모양이 동일함을 Node에서 대조했다. 새 전송값·새 공개 필드 없음(D-65).
