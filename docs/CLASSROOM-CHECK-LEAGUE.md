# 전력 리그 실제 기기·실제 연결 확인

로드맵 완성 기준 2의 한 줄, "혼자 하기·6팀 멀티가 실제 기기(태블릿)와 실제 연결(Supabase)에서 끝까지 돈다"를 선생님이 직접 확인하는 순서다. 자동 검사로 이미 확인한 것과 사람이 봐야 하는 것을 먼저 나눈다(아래 '자동 검사로 확인한 것'). 실제 태블릿, 교실 무선망, 6팀 12달 완주, 손가락 조작은 사람이 봐야 한다. 장면별 학습 흐름(S1~S8이 '잘 됨'인지)은 영상 재확인으로 따로 판정한다. 기록에는 통과·미통과, 시각, 기기 종류와 OS 판, 관찰 메모만 남기고 사람 이름·학생 정보는 적지 않는다.

| | 0. 준비 | 1. 혼자 하기 | 2. 6팀 멀티 |
|---|---|---|---|
| 누가 | 교사 | 교사 1명 | 교사 1명(진행자) + 태블릿 조작 도우미(사용자 결정) |
| 기기 | 노트북, 태블릿 | 수업에 쓸 태블릿 1대 | 노트북 1대(프로젝터) + 태블릿 6대 |
| 시간 | 수업 전날까지 | 약 40~60분(추정, 영상 2차의 자동 녹화는 13분) | 100분(2차시 분량) |

## 자동 검사로 확인한 것(2026-10-20, 맥 로컬, 실제 Supabase 프로젝트)
- **실제 연결 흐름:** `live.py`(한 컴퓨터의 브라우저 창 넷 — 진행자 1·팀 3, 3달)가 436/0으로 두 번 연속 통과했고, 계통 수입(D-74)·S8 바로가기 등을 합친 판(480130e)에서 큰 스냅 단계를 더해 446/0으로 다시 통과했다. 상태 일치, 새로고침 복구, 자유 서술 미전송, 공개 상태 봉투(D-77) 펼침을 본다. 요청에서 진행자 스냅 수신까지 지연은 중앙값 377~414ms, 최대 490~643ms였다. 개발용 맥 한 대의 네트워크에서 잰 값이라 교실 무선망·태블릿에서는 다를 수 있다.
- **메시지 크기:** 실제 채널은 한 메시지 256KB까지 전달하고 300KB부터 거부했다(무료 요금제 공식 상한과 같음). 6팀 판의 서명된 진행자 스냅은 첫 달 결과 97~104KB, 12달 최대 126~134KB, 36달 최대 150~160KB(Node 계산)이고, 12달 최대 129,597B·36달 최대 159,278B를 실제 채널로 보내 도착을 확인했다(`live.py --bigsnap-only` 10/0, 36달 218ms. 480130e에서 다시 12달 129,472B·36달 159,715B, 10/0, 217~282ms). 6팀 36달 최대 스냅도 상한보다 약 96KB 작다.
- **확인하지 못한 것:** 6팀이 동시에 요청을 보낼 때의 지연, 태블릿 브라우저(사파리·크롬)의 웹소켓 유지, 화면이 꺼졌다 켜질 때의 재연결, 학교망 필터. 아래 2가 이것을 본다. 한 가지 위험은 이미 보였다. 개발용 맥에 다른 작업이 몰려 1분 부하가 60~190일 때, 한 브라우저 안 6팀 녹화(실제 Supabase가 아닌 탭끼리 연결)에서 팀 화면에 '진행자 화면과 연결을 확인하는 중' 안내가 뜨고 팀 계획이 진행자에게 15초 넘게 반영되지 않았다(2026-10-20, 두 번). 부하가 낮을 때는 같은 녹화가 12달 끝까지 돌았다. 느린 태블릿에서도 같은 일이 생기는지는 아래 2에서 본다.

## 0. 준비
1. **https 주소(멀티).** 6팀 멀티의 태블릿은 https 주소로 접속해야 한다. 노트북 IP의 http 주소로 들어오면 요청 서명에 필요한 WebCrypto를 쓸 수 없어 팀이 자리에 앉지 못한다(README, D-64). 지금은 https 배포가 없으니(MERGE-PLAN §1) 배포 방식을 먼저 정한다. 혼자 하기에는 코드상 이 검사가 없어 노트북의 http 주소로 먼저 해 볼 수 있다. 다만 http에서는 활동지 복사가 클립보드 대신 복사 입력 창으로 뜬다.
2. **Supabase 프로젝트.** 대시보드에서 프로젝트가 활성인지 본다. 일시 중지돼 재개한 적이 있다(PROGRESS 2026-10-05). 앱에는 프로젝트 주소와 공개 키만 넣는다. 앱은 `sb_secret_`가 든 비밀 키와, 예전 형식(eyJ…로 시작하는) 키 가운데 역할이 anon이 아닌 키(service_role 등)를 로비·참가 링크·연결 직전에 거부한다. 이 검사는 입력 실수를 막는 장치이지 키의 진위를 검증하지는 않으므로, 대시보드에서 publishable 또는 anon 표시가 있는 키만 복사한다. 이 주소와 키는 참가 링크에 담겨 모든 태블릿으로 간다.
3. **교실 무선망.** 교실에서 노트북으로 온라인 방을 하나 만들고 태블릿 한 대로 참가해 본다. 학교망 필터가 `supabase.co` 웹소켓을 막으면 여기서 멈춘다.
4. **태블릿.** 충전, 화면 자동 잠금 끄기 또는 길게. 개인 정보 보호(시크릿) 창은 닫으면 기기 기록이 사라지므로 쓰지 않는다.

## 1. 혼자 하기 12달
1. 태블릿에서 전력 리그 → 혼자 하기 → 평택, 12달, 균형 성향. '날씨·사건 · 연습 방식'을 펼쳐 연습 방식을 '약속 연습'으로 바꾼다(기본인 '자유 실험'은 약속을 건너뛸 수 있다).
2. 매달 한 바퀴를 손가락으로만 한다. 근거 하나 → 설비 하나 배치(첫 탭 미리보기, 둘째 탭 설치) → 1주 시험 → 약속 → 준비 → 결과와 원인 카드 → 다음 달 바꿀 것. 원인 카드를 연 뒤 결과가 뜰 때까지 걸린 시간을 한 번 잰다.
3. 6월 결과 뒤 브라우저를 완전히 닫았다가 다시 열어 이어 한다.
4. 가로로 6달, 세로로 6달 한다.
5. 12월 끝 화면에서 성찰과 활동지 복사를 눌러 본다.
- **통과:** 12월 끝 화면까지 막힘이 없다. 다시 연 뒤 같은 달·같은 상태에서 이어진다. 설치 오조작이 달마다 1회 이하다. 두 방향 모두 글자 잘림·겹침이 없다.

## 2. 6팀 멀티 12달
1. **방 만들기(진행자).** 노트북에서 https 주소 → 전력 리그 → 로비의 '연결 방식'을 온라인으로 바꾸고 프로젝트 주소·공개 키 입력 → 6팀, 12달, 수업 시간 100분 → 새 방 만들기. 로비 안내대로라면 한 달에 계획 약 5분 50초, 결과 약 2분 30초다.
2. **참가.** 다섯 대는 진행자 화면의 '참가 링크 복사'로 받은 링크로 들어온다. 앱에 QR 만들기는 없다. 링크에 프로젝트 주소와 공개 키가 들어 있으므로 외부 QR 생성 사이트에 넣지 않는다. 한 대는 로비의 '연결 방식'에서 온라인을 고르고 주소·키를 넣은 뒤 8자리 방 코드를 쳐서 들어온다. 이 칸을 비우면 '이 기기(탭끼리)'로 남아 방을 찾지 못한다.
3. **12달 진행.** 매달 계획 → 연계선 제안·수락 한 번 이상 → 준비 → 운영 → 결과·원인 카드·일지. 달마다 계획과 결과에 걸린 시간을 적는다. 첫 달에 두 가지를 손가락으로 본다. 도시 지도의 지명표(예: '○○ 방향 · 이웃 도시 연결점') 아래 칸을 눌러도 설치되는지, 결과 서랍의 '예측과 실제를 비교했어요' 체크 상자가 문구를 눌러도 체크되는지(영상 2차 M7·M11).
4. **끊김과 복구.** 3월 계획 중에 팀 태블릿 한 대를 새로고침한다. 6월 계획 중에 다른 태블릿의 무선을 1분 끊었다 켠다. 9월 결과 뒤 또 다른 태블릿의 브라우저를 완전히 닫았다가 열어 로비의 '이어서: ○○ 팀' 버튼으로 돌아온다. 1차시 끝에 진행자 브라우저를 닫고, 2차시 시작 때 '이어서 진행'을 누른다.
5. **끝.** 12월 끝 화면과 순위표를 보고 진행자 화면의 '기록 내려받기'로 공개 상태 CSV를 받는다.
- **통과:** 모든 팀이 12달의 준비·운영을 마쳤고, 멈춰서 방을 새로 만든 일이 없다. 결과가 나올 때마다 진행자 화면과 태블릿 두 대의 현금·정전률이 같다. 새로고침·끊김·브라우저 다시 열기·진행자 재시작 뒤 같은 자리·같은 달로 돌아오고 써 둔 일지가 남아 있다. 팀 화면의 '진행자 화면과 연결을 확인하는 중' 안내(진행자 메시지가 10초 넘게 없을 때 켜짐, D-64)는 진행자와 무선이 돌아온 뒤 1분 안에 사라진다. 팀이 쓴 일지·이유 글이 진행자 화면에 나타나지 않는다(D-59). 100분 안에 12달을 끝내는지는 통과 조건이 아니라 실측값으로 적는다.

## 사용자에게 정해 받을 것
- https 배포를 무엇으로 할지(예: 공개 저장소의 GitHub Pages — 지금 도시 이름은 실제 지명이다, D-58·D-65).
- 참가 링크를 태블릿에 어떻게 전할지(메신저, 학급 게시판 등). 링크에 공개 키가 들어 있다.
- 6팀 확인의 태블릿 조작을 누가 할지(동료 교사, 학생 도우미, 교사 혼자 여러 대).
- 이 확인을 시범 수업 전에 따로 할지, 시범 수업 1차시를 겸할지. 학생이 참여하면 D-65에 따라 가상 도시 이름 전환이 먼저다.
