# 인계 기록

## 언제
- 큰 단계(구현, 검사, 커밋, PR)가 끝날 때마다.
- 하위 에이전트를 띄우거나 그 결과를 받았을 때.
- 대화가 길어져 압축이 다가올 때, 세션을 넘길 때.

## 무엇을 고치나: docs/PROGRESS.md
1. **마지막 갱신** 날짜.
2. **사용자가 정한 방향**: 사용자 원문 요지를 새로 받았으면 덧붙인다. 지우지 않는다.
3. **PR 현황** 표: 번호, 브랜치, 상태.
4. **현재 상태**: 끝난 것 / 진행 중인 것(무엇을 어디서 돌리는지, 결과 파일 위치) / 커밋 여부.
5. **다음 단계**: 번호를 매겨 바로 실행할 수 있게. 명령과 경로를 적는다.
6. 새 결정은 PROGRESS가 아니라 **docs/DECISIONS.md**에 D-번호로 추가한다(맥락·대안·근거·결과·상태). 검사 제약에서 나온 결정은 어느 검사인지 적는다. 결정을 바꾸면 이전 항목 상태를 "대체됨(D-xx)"으로 고친다.

## 원칙
- 사실만 쓴다. 돌리지 않은 검사를 통과라고 쓰지 않는다.
- 스크래치패드·/tmp 경로는 세션마다 사라진다. 계속 필요한 스크립트는 저장소(`tests/` 등)로 옮기거나 '없으면 다시 만든다'고 적는다.
- 오래 유지할 규칙(사용자 선호, 계약, 검사 제약)은 PROGRESS가 아니라 `CLAUDE.md`에 올린다. CLAUDE.md는 짧게 유지한다.
- 고친 뒤 커밋할 브랜치가 있으면 함께 커밋해 원격에도 남긴다.
